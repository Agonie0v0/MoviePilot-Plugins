# 115秒传等待 · MoviePilot V3

版本 1.0.2（测试版），支持 MoviePilot **3.1.x** 内置 115。本地视频的复制和移动整理未命中秒传时，在原整理记录中显示失败，由后台队列重试；远端文件确认后，交给 V3 原生持久整理计划完成整理，将**同一条记录**更新为成功。

## 安装和升级

在插件源添加 `https://github.com/Agonie0v0/MoviePilot-Plugins`，刷新市场并安装或更新“115秒传等待”。V3 会加载 `plugins.v3/p115instantwait`，请勿使用 V2 的本地安装脚本。

升级 V3 前请先在 V2 完成或取消等待任务，保留插件数据目录和配置。V2 遗留任务会保留为暂停，只允许取消；需要在 V3 中重新发起整理。升级不会直接改写旧宿主数据库，也不会自动发送遗留任务的文件内容。

## 配置

| 设置 | 含义 | 默认值 |
| --- | --- | --- |
| 启用秒传等待 | 接管本地视频到内置 115 的复制或移动整理 | 关闭 |
| 任务状态通知 | 首次等待、达到上限和异常时提交 MP 渠道通知并写站内消息 | 开启 |
| 最多重试 | 不含首次尝试，0 表示首次失败即执行上限策略 | 3 次 |
| 最长等待 | 本轮等待时限；0 表示不限时 | 24 小时 |
| 达到上限后 | 选择“手动处理”或“强制上传”；次数、时间任意一项达到即执行 | 手动处理 |
| 重试间隔 | 秒，逗号分隔，超过列表后使用最后一项；允许 30～86400 秒 | 60,180,600,1800 |
| 扩展名 | 逗号分隔的本地视频扩展名 | 常见视频格式 |

配置页支持搜索多选任务，批量暂停、继续等待、强制上传或取消。“继续等待”重置本轮次数和时限；“强制上传”先试秒传，未命中便上传正文。普通上传使用独立线程，期间其他整理和自动秒传队列仍可运行。异常或源文件变化会暂停，不会因为上限策略自动绕过校验。

任务详情和日志显示原整理记录 ID、任务 ID、状态、累计尝试、本轮自动尝试和下次重试时间。MP 全局通知设置仍需开启相应渠道及“整理”/“手动处理”消息类型。

记录页显示入队时间，以及完成、结束或最近更新时间（按 MP 所在时区，精确到秒）。展开“最新结果”可查看失败原因；成功时按实际传输结果显示“强制上传成功”或“触发秒传成功”。强制上传操作仍可能命中秒传，此时显示“触发秒传成功”。缺少传输确认标记的旧记录显示“传输方式未记录”，不推测结果。

## 历史清理

配置页展开「历史清理」，两种操作可分别选择，保存时执行一次，随后自动取消勾选。

- **115 空暂存目录**：成功任务会自动尝试清理自己的空目录。勾选「保存时清理一次历史空暂存目录」可补清理以前留下的目录；后台检查插件队列中记录过的目标位置，不遍历整个网盘。旧记录丢失时，可在补充路径中逐行填写完整的 `/目标目录/.mp115-staging`，最多 100 个。
- **只清理空目录**：只识别 `.mp115-staging` 及其下 24 位任务 ID 目录。非空目录、其他命名目录和 `.mp115-backups` 不删除；等待、暂停、上传中及等待宿主回写的任务目录保留。两个整理线程的创建目录与清理互斥，文件传输本身仍可并行。
- **插件已结束记录**：可搜索多选指定记录，或选择成功/失败/已取消状态与保留天数；条件清理覆盖全部历史，不受详情页最近 200 条限制。默认保留最近 30 天，填 0 清理全部匹配记录。按结束时间计算，不按文件日期。
- **保护恢复信息**：未完成任务不能删除；同批次仍有未完成任务时，成功记录会跳过，等批次结束后再清理。只删除插件队列记录，MoviePilot 原整理历史、本地源文件及远端文件保留。
- **先删记录也能清目录**：删除记录时单独保留曾使用的暂存目录位置，之后仍可补清理。选择记录的操作不可撤销，请按需勾选。插件关闭时也可清理本地记录，远端目录清理需要启用插件。

重新打开配置可查看最近一次清理的删除、保留、缺失和异常数量。清理沿用接口请求间隔，不增加定时扫描；异常不会让已成功任务重新上传或回写。关闭/重新配置插件会停止后台清理，可再次勾选继续。暂存目录应由本插件独占使用，避免其他程序在远端空目录检查与删除之间写入文件；115 的检查和删除是独立请求。

## V3 的完成流程

1. V3 冻结并持久化原整理计划；插件返回等待结果，由宿主写原失败记录。
2. 独立线程计算哈希、等待秒传，或按操作进入普通分片上传。源文件保留，文件先进入目标父目录的 `.mp115-staging/<任务ID>`。
3. 远端文件校验通过后，显示“等待 V3 回写”。插件只登记原失败任务的重试意图；宿主恢复调度器取得任务租约后重放原计划，执行最终移动、覆盖判断和移动模式的源删除。
4. 完成前再次确认精确目标文件 ID 和文件大小；可取得 SHA1 时同时核对。宿主更新原记录并发送成功事件，插件标记完成。

“等待 V3 回写”期间不可重复手动操作，避免与宿主完成步骤竞争。原生恢复调度器有调度延迟，此状态不会直接显示成功。若 V3 将外部步骤隔离为人工复核，需要先在宿主整理队列核对和处理，再恢复插件任务。

旧目标文件会移动至 `.mp115-backups/<任务ID>`，不自动永久删除。取消任务保留源文件、暂存文件和备份，需要时可人工核对后清理。

## 支持边界

- 单视频文件、本地到内置 `u115`，原生 `copy` / `move`；不支持蓝光原盘目录、替换整个旧目录、外部存储接管和缺失持久任务身份的同步调用。
- 未匹配的字幕、NFO、图片等继续走 MP 原生整理；它们可能先于视频完成。批次刮削等视频完成或取消后释放。
- V3 自身拥有媒体识别、计划、执行步骤、任务租约和整理历史。插件不直接操作宿主 ORM 或会话。
- 对 **3.1.0 <= 版本 < 3.2.0** 及内部接口进行双重校验，接口不符时停止接管并提示错误。
- 已完成隔离测试，尚未在实际 V3 服务器和真实 115 账号上验证授权、上传和通知投递。首次升级建议用一部可恢复的本地测试视频确认完整流程。

验证依据、命令与限制见 [兼容性报告](../../docs/v3-compatibility.md)。
